# R4: target path supervision with cross-resolution calibration

- **Question:** Does genuine target-side first-accepted Newton-path fine-tuning improve the best measured path-source pipeline when paired with its two-step 64-to-256 commutator calibration?
- **Why this follow-up:** The R2 path-source + comm256 candidate is the best current HR-dev model, while the isolated R3/R4-era first-path arms did not consistently beat endpoint controls and did not include comm256. This focused interaction pair tests the missing combination without opening another broad hyperparameter search.
- **Arms:** Reuse the frozen Stage-2 `pilot_pathsource_comm256` as A0 (path-source + NLT + final-only/comm256 target calibration). New A1 uses `newton_correction_first`; matched A2 uses `endpoint_increment`. Both start from the same path-source checkpoint, train the same NLT adapter with Adam/config inherited from `allen_cahn_v2_calibration.yaml`, run 100 cosine epochs, and use the same two-step 64-to-256 commutator loss (weight 0.05). A1/A2 additionally share layer 1, gradient ratio 0.05 and gamma-2 annealing. This reuses the existing A0 checkpoints and avoids duplicate training.
- **Frozen data:** six existing development boundary families/tasks `[0,1,2,3,4,5]`; model seeds `[0,1,42]`; support seed `271829`; nested `m=4`; eight independent LR validation rollouts. The saved first accepted corrections are genuine LR Newton labels. No new model or support seed is introduced.
- **A0 artifact alias:** the Stage-2 seed-1 `pilot_pathsource_comm256` evidence is stored under the audited immutable retry ID `pilot_pathsource_comm256-recovery1`; it is the same model seed, support draw, task matrix, and selected method. The paired summarizer pins this alias explicitly.
- **Selection/evaluation:** each task checkpoint is selected only by 64x64, 20-step LR validation. Evaluate the two predeclared arms on the pinned 256x256 HR-development indices only after all LR runs finish. Report paired family × seed comparisons against one another and the prior pathsource+comm256 reference. HR-dev is a development comparison, not the frozen confirmation set.
- **Execution:** serially on GPU0; separate single-GPU jobs only. No multi-GPU training. Do not read or generate confirmation query data.
- **Budget:** 36 new LR target cells plus 36 HR-dev evaluations; reuse the 18 A0 LR/HR cells. Stop before exceeding 8 GPU-h for this card; budget headroom is checked against `docs/BUDGET.md`. After the first complete A1 cell measured 0.2015 GPU-h, the initial 7 GPU-h estimate was amended to 8 GPU-h before completing the matrix; this remains within the current exploration headroom. Three two-epoch smokes (one per arm) are implementation-only and excluded from ranking.
- **Decision rule:** retain A1 and A2 regardless of outcome. Compare A1 with the matched A0 and A2 across seeds/families. A1 supports a target-path-specific development signal only if it has repeatable, practically meaningful paired advantage over both. If the three-arm combination does not improve on existing comm256, conclude that target path supervision did not improve the development leader. This card does not alter the frozen confirmation protocol.
